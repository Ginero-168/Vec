# ชุดเทคโนโลยีสำหรับแอปแปลงภาพเป็นเวกเตอร์

ตรวจข้อมูลจากเอกสารและ repository ทางการ ณ 19 ตุลาคม 2026 เอกสารนี้เสนอการใช้ไลบรารีในแอปเดสก์ท็อปที่ต้องแก้บริเวณสี เส้นขอบ และจุดควบคุม Bézier ได้จริง การเลือกเวอร์ชันก่อนเริ่มพัฒนาควรล็อกเป็น tag หรือ commit และทดลอง build บนระบบเป้าหมาย เพราะ API และรายการ dependency เปลี่ยนได้

## ข้อเสนอ

ใช้ **C++20 + Qt 6.12** เป็นฐานของแอปและเอนจินเดียวกัน ใช้ **OpenCV 4.14** สำหรับงานภาพระดับพิกเซล, **LittleCMS 2** สำหรับ ICC, **Clipper2** สำหรับความสัมพันธ์ของรูปทรง และ **Eigen** สำหรับคณิตศาสตร์ของเส้นโค้ง เพิ่ม **libvips** เมื่อมีหลักฐานว่าการโหลดภาพใหญ่หรือ batch กินหน่วยความจำเกินเป้า เพิ่ม **Ceres** เมื่อการฟิต Bézier แบบ Eigen ที่เขียนเองไม่พอ เพิ่ม **ONNX Runtime** เฉพาะโมเดลที่ผ่านการวัดผลกับชุดภาพจริง **Skia** เป็นตัวเลือกสำหรับ renderer หาก Qt วาดฉากขนาดใหญ่ไม่ทัน เงื่อนไข Qt ที่ผู้ขายต้องทำตามแตกต่างกันระหว่าง commercial และ LGPL; จึงต้องตัดสินรูปแบบแจกจ่ายก่อนล็อกสแตก [Qt 6.12 LTS](https://www.qt.io/blog/qt-6.12-released), [Qt licensing](https://doc.qt.io/qt-6/licensing.html), [OpenCV 4.14 release](https://opencv.org/release/opencv-4-14-0/).

OpenCV 5.0 ออกแล้วในเดือนสิงหาคม 2026 แต่ข้อเสนอให้เริ่มกับสาย 4.14 และเปิดงานทดลองย้ายเป็น 5.0 แยกต่างหาก เป็นการเลือกเพื่อลดการเปลี่ยน API ระหว่างสร้างรุ่นแรก ไม่ใช่ข้ออ้างว่า 5.0 ใช้งานไม่ได้ [OpenCV 5.0 release](https://opencv.org/release/opencv-5-0-0/), [OpenCV 4.14 release](https://opencv.org/release/opencv-4-14-0/).

## เหตุผลของสแตก C++/Qt

Qt รองรับ Windows, macOS และ Linux พร้อม framework สำหรับแคนวาสที่ซูมและเลือกชิ้นงานได้ ขณะที่ OpenCV, Clipper2, Eigen และ Ceres มี C++ API โดยตรง ลดรอยต่อภาษาใน loop ที่ทำงานกับพิกเซลและ path [Qt platform introduction](https://doc.qt.io/qt-6/qt-intro.html), [QGraphicsView](https://doc.qt.io/qt-6/qgraphicsview.html), [Ceres overview](https://ceres-solver.readthedocs.io/latest/).

Tauri ใช้ Rust core กับ HTML ใน WebView และสื่อสารผ่าน message passing; เหมาะเมื่อทีมถนัดเว็บหรือ UI เป็นแบบฟอร์ม/แดชบอร์ดมากกว่าแคนวาสแก้ path หนัก ๆ. หากเลือกทางนี้ ต้องออกแบบการส่งข้อมูลภาพขนาดใหญ่และ FFI ไปยังไลบรารี C++ ที่เสนอ ซึ่งเป็นต้นทุนทางสถาปัตยกรรมที่ต้องพิสูจน์ด้วย prototype [Tauri architecture](https://v2.tauri.app/concept/architecture/), [process model](https://v2.tauri.app/concept/process-model/). SwiftUI เป็นทางเลือกที่ดีถ้าตัดสินใจทำเฉพาะผลิตภัณฑ์บนระบบ Apple; เอกสาร Apple ระบุขอบเขตเป็น Apple platforms [SwiftUI overview](https://developer.apple.com/documentation/technologyoverviews/swiftui).

## ขอบเขตและจุดตัดสินใจ

1. **รุ่นแรก:** Qt + OpenCV + LittleCMS + Clipper2 + Eigen. เขียนข้อมูลภาพและ topology ของรูปทรงเป็นชนิดข้อมูลของแอปเอง ให้ UI, core และ exporter ใช้โครงสร้างเดียวกัน. ใช้ Qt SVG แสดงตัวอย่าง แต่เขียน SVG export จากโครงสร้างรูปทรงนั้น ไม่ยึดรูปแบบภายในของ renderer [Qt SVG](https://doc.qt.io/qt-6/qtsvg-index.html).
2. **เมื่อภาพใหญ่หรือ batch ช้า:** วัด peak memory และเวลาโหลด แล้วเพิ่ม libvips สำหรับ I/O, resize และ pipeline ที่เหมาะกับ streaming. ลองกับไฟล์จริงก่อน เพราะการใช้ libvips คู่ OpenCV เพิ่มการแปลง buffer และ dependency [libvips README](https://github.com/libvips/libvips).
3. **เมื่อการฟิตเส้นมีข้อจำกัด:** เริ่ม Eigen สำหรับเส้นแต่ละช่วง. เพิ่ม Ceres เพื่อ optimize หลายเส้นร่วมกันเฉพาะเมื่อความต่อเนื่องของขอบหรือจำนวน control points ยังไม่ผ่านเกณฑ์; ปิด SuiteSparse ในการทดลอง build ปิดซอร์ส [Ceres tutorial](https://ceres-solver.readthedocs.io/latest/nnls_tutorial.html), [Ceres installation](https://ceres-solver.readthedocs.io/latest/installation.html).
4. **เมื่อรุ่นที่ไม่ใช้ AI มี baseline แล้ว:** ลอง ONNX Runtime กับงานที่มี ground truth เช่น mask ของผมหรือพื้นหลังซับซ้อน. เลือกโมเดลจากคะแนนภาพจริง เวลาประมวลผล ขนาดไฟล์ และสิทธิ์ของ weights. อย่าเพิ่มโมเดลเพียงเพราะ runtime รองรับ [ONNX Runtime C++](https://onnxruntime.ai/docs/get-started/with-cpp).
5. **เมื่อ renderer แสดงผลไม่ทัน:** profile จำนวน path, การ pan/zoom และการอัปเดตเฉพาะบริเวณ. พิจารณา Qt Quick scene graph หรือ Skia หลังมีตัวเลข; Qt Quick ใช้ backend อย่าง Metal, Vulkan และ Direct3D ตามระบบ [Qt Quick scene graph](https://doc.qt.io/qt-6/qtquick-visualcanvas-scenegraph.html), [Skia docs](https://docs.skia.org/docs/).

## เรื่องที่ยังต้องตรวจใน build จริง

- รายการโมดูล Qt ที่ใช้, สิทธิ์ของแต่ละโมดูล, วิธี link, notice, source offer และข้อกำหนด LGPL/commercial ก่อนแจกจ่าย [Qt licensing](https://doc.qt.io/qt-6/licensing.html), [Qt obligations](https://www.qt.io/development/open-source-lgpl-obligations).
- SBOM ของ codec และ optional dependencies ที่มากับ OpenCV, libvips, Skia, Ceres และ ONNX Runtime ตามตัวเลือก build จริง. สิทธิ์ของ core project ไม่ครอบคลุมทุก dependency [Ceres licensing note](https://ceres-solver.readthedocs.io/latest/license.html), [Skia build guide](https://github.com/google/skia/blob/main/site/docs/user/build.md), [ONNX third-party notices](https://github.com/microsoft/onnxruntime/blob/main/ThirdPartyNotices.txt).
- การแสดงสี ICC และ alpha ให้ตรงกันตั้งแต่ import, preview, raster comparison จนถึง export. LittleCMS ทำ color transform ได้ แต่การต่อขั้นตอนเหล่านี้เป็นหน้าที่ของแอป [LittleCMS](https://github.com/mm2/Little-CMS).
- ข้อจำกัด format output ที่สัญญากับผู้ใช้. Qt SVG ระบุความสามารถด้าน rendering/displaying SVG จึงไม่ควรอนุมานว่าใช้แทนตัวส่งออก AI หรือ EPS ได้ [Qt SVG](https://doc.qt.io/qt-6/qtsvg-index.html).
